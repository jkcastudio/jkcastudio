## Ground rules

These apply to every coding agent working in this repo. They are not negotiable and
they are not restated in `CLAUDE.md`.

- **Gates before done.** Run the repo's own gates (listed above) and read the output.
  A build that passes because a gate was skipped is not a pass. Nothing ships with
  visible `[TK]` text.
- **Verify locally.** Build and look at the change at 375 / 768 / 1280 and in the
  mobile menu before calling it done. Screenshots beat assumptions.
- **Never deploy production without the owner's go.** Preview and demo deploys are
  session work. A custom domain ships only on an explicit, per-release approval, using
  the deploy line above and no other.
- **No sign-in.** Do not log into dashboards, registrars, mail, analytics, or any
  account. Do not read credential stores, `~/.config`, or `.env` files. If a task needs
  a secret, stop and say so.
- **No client assets in this repo** beyond web assets that are actually deployed. No
  brand kits, photo libraries, exports, backups, contracts, or contact lists.
- **No AI attribution anywhere.** No `Co-Authored-By`, no "Generated with", no AI
  trailers or headers on commits, PRs, files, or deliverables.
- **Tokens, not values.** Colors, type, and spacing come from the design tokens this
  repo defines. No hard-coded hex/rgb, no arbitrary utility values.
- **Invent nothing.** No unverified claim, feature, stat, credential, price, address,
  or phone number. If a fact is not in the repo or the brief, it does not go on the page.
- **US spelling.** Rendered copy uses US English.
- **No em dashes in rendered copy.** Use commas, periods, or a colon. This applies to
  anything a visitor reads, not to code comments.

## Lessons

`LESSONS.md` at the repo root is the correction log: one line per correction, dated,
what went wrong and the rule that prevents it. Read it before starting work here, and
add a line after any correction from the owner or a reverted run. It stays short; a
lesson that stops applying gets removed, not archived.

- **Two reverts, one cause, stop.** When a loop or a crew run reverts twice for the same
  reason, the run ends and the plan changes. Do not re-run the same brief a third time.
- **Plan before a build of three or more steps.** Tooling and automation get a written
  plan (scope, gates, what may be edited) before the first edit, the same way pages get a
  comp gate. The plan names what the gate cannot reach.

## Handoff

Leave the tree in a state the next agent can read: a clean build, a plain commit message
with no AI attribution, and any unfinished decision written down rather than guessed at.
Blockers and architecture conflicts get escalated, not improvised around.
